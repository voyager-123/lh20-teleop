# L20-10 无触觉遥操的驱动延迟优化（2026-11-02）

适用于 SDK v2、CAN、L20-10/L20-11/G20、关闭触觉的组合。其他型号、SDK v1、触觉或 Modbus 仍走原调度。拇指 agile 映射、模型限位/限速、故障处理、实际路径 CAD 与反馈变化重检均未调整。

## 调度

新收到的位置始终替换尚未发送的位置，包括 ROS 的 `array('d')`；接下来的一轮先发送位置，再读位置。每轮最多追加一种信息查询：故障优先，查询开始间隔目标 100 ms；速度阈值、电流、温度、扭矩每 150 ms 轮换一种。繁忙时允许延后，不追赶补发；速度阈值不再每轮重复读取。没有订阅者时不作对应查询，不自动写速度、扭矩、清故障或启动姿态。

保留底层每个 CAN 帧的 3 ms 等待及各查询方法自带的等待。所有读写仍在同一个 ROS 回调线程串行执行，没有并发抢占总线。独立食指探针仍只走单指通道，存在整手控制器时仍拒绝探针。

发布线程只在新位置查询完成后发布位置，只在新故障查询完成后发布信息；不再把同一次查询缓存反复发布成新反馈。因此查询线程阻塞时，现有控制桥的反馈超时保护能生效。注意底层查询仍返回接收线程维护的缓存，查询完成不等于证明每个电机都有新的应答。

## 离线等待预算

执行从真实源码提取的驱动方法，仅将 CAN 发送和 sleep 替换为记录与虚拟时间。下列数字是代码中的固定等待，不是实测的电机响应时间，也不包括 ROS 调度和设备应答。

| 场景 | 原版 | 新版 |
| --- | ---: | ---: |
| 无新动作，仅位置反馈 | 45 ms（含速度查询） | 17 ms |
| 新位置 + 位置反馈 | 60 ms | 32 ms |
| 新位置 + 信息查询 | 143 ms（集中查询全部信息） | 47–50 ms（每轮一种） |
| 回调开始至第一帧位置写出 | 39 ms | 0 ms（移除前置查询等待） |

持续负载虚拟测试检查：每轮固定等待不超过 50 ms，位置每轮查询，故障不被低频信息饿死，四种信息持续轮换。实际硬件/系统耗时可能更长，不能将 50 ms 当成实时保证。

## 下一次实测日志

`hand_info.sdk_io` 记录同机单调时钟的收令、位置发送开始/结束、位置查询开始/结束、各信息查询完成时间和本轮耗时。控制桥将其保存为 `kind=sdk_io` 记录。发送结束只表示主机发送方法返回，不表示电机已达到目标；查询时间不是 CAN 应答时间。该记录用于将驱动排队/发送与后续跟随区别开来。

此更新需要重启正在运行的 SDK 和遥操进程；仅关闭/重开相机而继续复用旧 SDK 不会加载新的驱动调度。现有 `--thumb-root-mode agile`、拇指接线选择、故障策略均沿用原启动参数。
