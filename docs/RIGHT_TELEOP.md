# 右手整手遥操（2026-11-05 更新）

默认启动命令：

```bash
/home/sjtu/linker_hand_ros2_sdk/lh20-right vision
```

已在工程目录时可用 `./lh20-right vision`。默认右手整手、Vector、agile、segments、swapped。启动脚本自动切换环境，并启动或复用右手 SDK 与右手控制桥。左手入口仍保持整手、Vector、agile、segments、swapped。

先接好右手电源、USB-CAN 和相机，确认 `can0` 为 UP、1 Mbit/s。右手使用 CAN ID 0x27；左手为 0x28。需要本机密码的 CAN 配置在本机终端执行。右手身份查询没有回复时不会启动 SDK 或控制桥。

```bash
ip -details link show can0
# 仅在接口尚未配置好时，退出所有控制程序后执行：
sudo ip link set dev can0 down
sudo ip link set dev can0 type can bitrate 1000000
sudo ip link set dev can0 up
```

## 可选入口

```bash
./lh20-right vision --preview
./lh20-right vision --self-test
./lh20-right vision vector --thumb-root-mode directions
./lh20-right vision dexpilot
./lh20-right vision dexpilot --self-test
```

`--preview` 仅视觉预览，不输出动作。`--self-test` 不连接相机或电机；DexPilot 的模型拟合自检暂时关闭 pinch 投影，避免把人为改变的投影目标当成原始 FK 目标，实际运行的 0.03 / 0.05 m 投影和滞回保持不变，并有专门回归检查。切换其他模式仍会控制真实手。

## 右手适配依据

- 新增右手独立模型包，复制已有右手 L20 模型及原始网格，不镜像或覆盖左手模型。
- 新增 `l20_10_right_factory.json`，来自既有右手 G20 厂家转换表与已记录的 MCP 侧摆符号适配；取厂家范围、模型范围及从动关节约束的交集。这个模型适配不是本机逐轴实测标定；部分运动范围会受到模型约束。
- 2026-11-05 用户反馈右手拇指侧摆/横摆疑似与左手相同地互换，右手固定入口现默认 swapped；将模型 roll/yaw 一致映射到协议通道 10/5，视觉编码、反馈解码、速度和 CAD 同步使用这一适配。可用 `./lh20-right vision --thumb-axes native` 对比交换前的通道，仍会控制实物。当前新适配需要用户复测方向。
- 保留三段拇指单位方向优化、agile 几何引导、自适应滤波、最新相机帧、真实指尖参考、按模型速度小步发送及完整路径 CAD。
- 根据检测器左右 MANO 坐标变换的差异，右手根部引导使用 `diag(-1,-1,1)` 转到左侧引导特征的约定；原右手方向目标与几何模型不变。这仍是控制映射，需用户实际确认三轴方向。
- 左右手分别检查相应的身份、模型摘要、配置摘要、ROS 话题、IPC 会话和日志；相反侧的数据包会被拒绝。
- 右手沿用低延迟 G20 调度；2026-11-05 用户明确授权右手参照左手，默认 ignore-64-128。仅忽略单独 64 或 128，保留原始故障日志；组合值 192、其他故障与反馈超时仍停止。

## 身份登记与固件

首次启动时只读查询 0x27 身份，要求设备身份为右手 L20-10（`LHT20-010-...-R-...`），随后写入本机 `teleop/data/right_device_identity.json`，下次拒绝不同身份。可用 `LH20_RIGHT_EXPECTED_IDENTIFIER` 显式约束预期身份；它与本机登记冲突时拒绝启动。不会把左手身份写入右手登记。

当前右手转换资料的固件范围为 1.0.6。控制桥读取设备信息并检查固件；固件不一致、异常故障、过期反馈、重复驱动或竞争控制器均拒绝输出。首次软件模型自检通过不代表设备身份、真实关节方向或机械角度已经标定。

## 2026-11-05 右手接通与侧摆范围修正

本机右手 CAN 0x27、序列号 L20-10 right (local identity omitted)、固件 1.0.6 已只读核验并登记；当前原始故障为零。断电重联后用户确认四指和拇指张开，读取四指侧摆为 [254,168,5,0]，CAD 无接触。

右手此前使用旧 L20 URDF 的 ±0.17 rad 侧摆范围，不能表示厂家 G20 转换表中合法的 ±0.23 rad。派生模型只把四指 MCP roll 范围改为厂家 ±0.23 rad，保持网格、轴、坐标适配、mimic、速度、其他关节范围和故障策略不变；同步固定新模型/映射哈希。它仍是基于厂家旧右手几何的派生模型，并非厂家发布的完整 G20 右手 CAD，也不是逐轴实测标定。

实机视觉随动尚需验证。四指并拢时若目标加深接触仍会被拒绝，不要绕过 CAD 检查。日常命令保持 `./lh20-right vision`。

## 2026-11-05 右手故障策略

右手启动时拇指通道 5、10 从零变为 128，旧 stop 策略使启动停止。用户明确授权后，日常 `./lh20-right vision` 自动采用左手已有的 `ignore-64-128` 策略，无需附加参数。只忽略等于 64 或等于 128 的单独原始值，不执行按位清除；192 等组合值及其他故障仍停止。保留 raw_fault_change 和 ignored_fault_codes 日志，身份、固件、时效、速度和 CAD 检查继续生效。

## 2026-11-05 拇指通道与延迟优化

保持原启动命令，右手默认由 native 改为 swapped。只交换拇指侧摆/横摆的两个协议通道，不变更其他关节、厂家角度表或模型几何；这一适配与左手使用的同类设置一致，实际效果仍需用户确认。`--thumb-axes native` 可显式恢复原通道对比。

刚才右手日志中，目标发出时图像年龄中位数 52 ms，近期左手日志约 48 ms；右手 275 次 CAD 结果因反馈已变化而重查。新增批量世界坐标包围盒筛选，只有确定分离的网格对可以跳过，可能接触的零件仍使用原精确网格和完整深度查询。非零碰撞查询 margin 或无效包围盒回退全量查询。路径采样密度、接触恢复、速度、故障和反馈时效规则不变。

从刚才右手实录抽取 77 段路径对照全量算法，结果一致，CAD 耗时中位数 6.7 -> 2.8 ms、P90 11.0 -> 4.7 ms。这是同一路径的离线耗时，不是实机端到端延迟。左右手两种拇指适配均做随机姿态全量/筛选碰撞与深度对照，以及真实接触路径回归。
