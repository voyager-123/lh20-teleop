# 控制流程与初稿配置

## 数据怎么流动

```text
RGB 摄像头 → MediaPipe 21 点及世界坐标
          → dex-retargeting 向量优化（16 个独立关节，mimic 展开为 21）
          → 厂家左手角度 / raw 计数转换 + swapped 拇指通道适配
          → 本机 Unix socket（时间戳、序号、模型与配置摘要）
          → ROS2 控制桥：反馈、速度、卡滞与 CAD 路径检查
          → 厂家 ROS2 SDK → SocketCAN can0 → L20-10 左手
```

视觉和 ROS 分属两个 Python 环境。会话管理器自动启动或复用唯一 SDK，启动控制桥和摄像头，只清理它自己创建的进程。ROS 发现范围限制在本机，避免另一台电脑上的右手 SDK 干扰。

## 为什么这只手用 swapped

厂家原始定义为拇指侧摆 / roll 在槽位 5、横摆 / yaw 在槽位 10。本次实机反馈中，两轴使用互换适配后基本动作符合预期，因此初稿入口选择 `swapped`。

适配同时用于目标编码、反馈解码、角速度限制和 CAD 模型检查；不是只交换发送数组。原厂家导出的 256 × 16 转换样本保留不变。`native` 和 `swapped` 使用不同摘要，视觉和控制端不一致时拒绝目标。

这是当前设备上的经验配置；尚未证明所有批次 LH20 都需要互换。厂家槽位标签和实际机械轴的差异原因仍待逐轴测量确认。对比预览：

```bash
./lh20-left vision --preview --thumb-axes native
./lh20-left vision --preview --thumb-axes swapped
```

## 控制约束与异常处理

- 16 个有效 raw 槽位是 0～10、15～19；预留槽位 11～14 的命令始终为 255。
- 目标最多 30 Hz。每次增量按模型角速度和实际经过时间计算，已移除“每次固定 1 计数”的整手速度瓶颈；模型速度不是厂家实测电机速度。
- 反馈最多约 300 ms、设备信息最多 1.5 s、视觉目标最多 250 ms；过期或竞争发布者仍会停用控制。
- 延迟容差按关节角度换算 raw 计数，避免正常反馈滞后造成全局退出。
- 持续不动的关节单独冻结，其余关节继续。向相反方向做出至少 3 个 raw 计数的目标变化，可释放该关节。丢失人手不会自动重试同方向硬推。
- **针对这次用户确认的左手，精确 raw 故障码 64、128 不触发退出，仍记录原值。** 192 等组合码和其他故障照常处理。这不是通用厂家故障解释，也不应直接套用到未验证设备。
- CAD 按约 0.01 rad 间隔检查命令路径。新碰撞和已有碰撞加深会阻止该目标；继续接收新手势，不锁死摄像头。起始网格已有重叠时，允许保持或逐步减小重叠，不能累计放宽容差。
- Q / Ctrl+C 停止新目标，不自动归零、回位、清故障或提高速度 / 扭矩设置。

## 目前的范围

这是基于 MediaPipe 和向量优化的单摄像头遥操原型。左右手主入口曾用于不同阶段，但这次发布维护和验证的是 **左手整手**。右手整手控制、旧录制回放、SPIDER、DexPilot 特定优化方法、触觉闭环和物体碰撞没有纳入本次成果。

`bridge` 中保留了单指探测 / 旧回放模块作为共享函数的历史来源；它们依赖的旧录制和旧左右手模型未随公开副本提供，不属于此初稿支持的运行入口。请按 README 的命令使用。

CAD 基于厂家几何模型，只检查选定的手指间及掌部与远端网格；没有物体、真实软组织、动力学或设备几何误差补偿。摄像头遮挡、尺度和坐标轴估计仍会影响跟随效果。下一步应记录端到端延迟、逐轴方向 / 范围和任务表现，再增加更强的重定向目标。
