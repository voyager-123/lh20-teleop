# 控制流程与初稿配置

## 数据怎么流动

```text
RGB 摄像头 → MediaPipe 21 点及世界坐标
          → dex-retargeting 向量优化（16 个独立关节，mimic 展开为 21）
          → 厂家左手角度 / raw 计数转换 + swapped 拇指通道适配
          → 本机 Unix socket（时间戳、序号、模型与配置摘要）
          → ROS2 控制桥：反馈、速度、卡滞与 CAD 路径检查
          → 厂家 ROS2 SDK → SocketCAN can0 → L20-10 左手
```

视觉和 ROS 分属两个 Python 环境。会话管理器自动启动或复用唯一 SDK，启动控制桥和摄像头，只清理它自己创建的进程。ROS 发现范围限制在本机，避免另一台电脑上的右手 SDK 干扰。

## 为什么这只手用 swapped

厂家原始定义为拇指侧摆 / roll 在槽位 5、横摆 / yaw 在槽位 10。本次实机反馈中，两轴使用互换适配后基本动作符合预期，因此初稿入口选择 `swapped`。

适配同时用于目标编码、反馈解码、角速度限制和 CAD 模型检查；不是只交换发送数组。原厂家导出的 256 × 16 转换样本保留不变。`native` 和 `swapped` 使用不同摘要，视觉和控制端不一致时拒绝目标。

这是当前设备上的经验配置；尚未证明所有批次 LH20 都需要互换。厂家槽位标签和实际机械轴的差异原因仍待逐轴测量确认。对比预览：

```bash
./lh20-left vision --preview --thumb-axes native
./lh20-left vision --preview --thumb-axes swapped
```

## 控制约束与异常处理

- 16 个有效 raw 槽位是 0～10、15～19；预留槽位 11～14 的命令始终为 255。
- 目标最多 30 Hz。每次增量按模型角速度和实际经过时间计算，已移除“每次固定 1 计数”的整手速度瓶颈；模型速度不是厂家实测电机速度。
- 反馈最多约 300 ms、设备信息最多 1.5 s、视觉目标最多 250 ms；过期或竞争发布者仍会停用控制。
- CAD 检查期间读回位置变化超过 2 计数时，丢弃该次检查结果并使用新反馈重检，不因正常电机运动重新等待三帧视觉。实际视觉丢失、无效输入或过期仍需重新确认连续有效帧；高于 30 Hz 的视觉流也能正常完成确认。
- 延迟容差按关节角度换算 raw 计数，避免正常反馈滞后造成全局退出。
- 持续不动的关节单独冻结，其余关节继续。向相反方向做出至少 3 个 raw 计数的目标变化，可释放该关节。丢失人手不会自动重试同方向硬推。
- **针对这次用户确认的左手，精确 raw 故障码 64、128 不触发退出，仍记录原值。** 192 等组合码和其他故障照常处理。这不是通用厂家故障解释，也不应直接套用到未验证设备。
- CAD 按约 0.01 rad 间隔检查命令路径。新碰撞和已有碰撞加深会阻止该目标；继续接收新手势，不锁死摄像头。起始网格已有重叠时，允许保持或逐步减小重叠，不能累计放宽容差。
- 整手目标被接触检查阻止时，尝试暂停涉及接触的手指，其余手指继续请求的增量。暂停轴反馈与上一条目标相差至多 2 计数时保持当前反馈，避免量化波动造成向旧目标微调、反而加深接触；偏差更大时保持旧目标。组合增量不能超过原候选的角速度预算，且整条路径必须再次通过相同的限位、碰撞与接触深度检查，否则仍停止该目标。每对网格只在两个物体的位姿完全不变时复用结果，降低静止接触的重复计算开销。
- Q / Ctrl+C 停止新目标，不自动归零、回位、清故障或提高速度 / 扭矩设置。

## 目前的范围

这是基于 MediaPipe 的单摄像头遥操原型，默认使用 Vector；可用 `./lh20-left vision dexpilot` 运行 DexPilot 方法组件对照。左右手主入口曾用于不同阶段，目前维护和验证的是 **左手整手**。右手整手控制、旧录制回放、SPIDER、触觉闭环和物体碰撞没有纳入本次成果。

`bridge` 中保留了单指探测 / 旧回放模块作为共享函数的历史来源；它们依赖的旧录制和旧左右手模型未随公开副本提供，不属于此初稿支持的运行入口。请按 README 的命令使用。

CAD 基于厂家几何模型，只检查选定的手指间及掌部与远端网格；没有物体、真实软组织、动力学或设备几何误差补偿。摄像头遮挡、尺度和坐标轴估计仍会影响跟随效果。下一步应记录端到端延迟、逐轴方向 / 范围和任务表现，再增加更强的重定向目标。

## DexPilot 方法组件对照

`./lh20-left vision dexpilot` 调用固定提交中的真实 `DexPilotOptimizer`，不是 Vector 别名，也不叠加 palm 实验约束。五指顺序为拇、食、中、无名、小指；使用手腕与指尖、指尖之间共 15 组向量，默认对应 MediaPipe 0、4、8、12、16、20 点。采用上游 3 cm 投影、5 cm 退出阈值，以及与原 Vector 相同的初始缩放 1.0 和滤波 0.6；这些是待实机评估的初始参数，不是已测量的人手比例标定。

实机记录发现直接将厂家底座原点与人手手腕对应，会让腕到指尖目标过短，四指末端因而持续弯曲。现按四指 MCP 中心对齐掌部参考，并按原模型骨链长度与当前人手骨链长度换算四根手指的腕到指尖目标；保留弯曲产生的相对缩短，不直接修改 PIP 角度或 raw 零位。十组指尖间向量及上游捏合投影、退出阈值保持不变。无效骨长暂停该帧，原 CAD 与限速仍检查最终运动。视觉记录用 `reference_alignment=mcp_center_bone_lengths_v1` 区分此适配；真人比例及实物接触仍需验证。

2026-10-25 后续实机反馈及 21:39 会话回放确认，此比例适配尚不完整：只改变腕到指尖向量会使十组指尖间目标与其不一致，小指目标也常超出模型的侧摆范围。统一向量和单独对齐各指 MCP 的离线实验均未充分解决问题，未部署这些实验。不能用模型生成姿态的自检结果宣称真人小指已可伸直。

同日 21:55 新会话继续出现小指及拇指偏差，但没有拇指单关节隔离事件，因此先前会话的隔离不能解释这次问题。1196 帧同输入回放显示 DexPilot 小指 PIP 目标中位数约 48°，Vector 约 10°；DexPilot 拇指 CMC pitch 约 96% 帧接近上限。两者复用同一厂家映射、限速与 CAD，这次模式差异首先说明 DexPilot 的目标适配问题。日常遥操使用 Vector，DexPilot 保留作未通过实机验收的方法实验。

预览模型显示视觉优化目标，不显示控制桥限速、CAD 暂停和单关节隔离后的实际执行姿态。该会话曾隔离 `thumb_cmc_pitch`，之后约 37 秒中实际反馈保持 raw 0～1，而视觉目标仍变化。用户补充“模型基本正确，实物不准确”时，应先核对这类目标与执行差异，再逐轴测量拇指通道、零位、量程及耦合；仅凭 raw 编解码互逆不能证明物理角度正确。

Vector 使用 `./lh20-left vision vector`；裸 `vision` 兼容原 Vector 默认配置。

原厂家模型没有指尖坐标。加载 DexPilot 时生成临时模型，仅在五个 distal 链接末端增加固定参考点：取末节 STL 沿局部 +Z 最后 1 mm 网格点的 X/Y 均值及最大 Z。参考点属于模型近似，未标定实物软指腹；它们不增加自由度，不修改原 URDF、关节范围、耦合关系或 raw 映射。CAD 和控制桥的模型身份仍使用原模型，避免把临时参考点当作新的碰撞或驱动模型。

视觉、控制桥须匹配 `vector` / `dexpilot` 算法标记；日志记录算法与配置摘要。DexPilot 自动保存人手关键点和目标的视觉 JSONL，便于后续重放同一输入比较 Vector。现阶段完成方法组件接入与离线检查，不代表已复现 DexPilot 原论文完整系统，亦不代表已改善实机捏取。

## 拇指姿态对比

### 2026-11-02 根部灵敏度与几何引导

使用者反馈前三根部轴迟钝。刚才会话的 1633 帧有效观测中，roll 低于 5° 占 62.9%，pitch 占 50.8%；1491 条命令中仅 31 条因 CAD 暂停拇指，拇指没有卡滞隔离事件。厂家模型在部分姿态下 yaw/pitch 的方向雅可比列高度相关，零姿态余弦约 0.984，因此“指骨方向接近”不保证三根部轴分别响应。单纯修改统一偏置、平滑或运动平面权重的试验没有解决这一问题，未保留到默认映射。

参考 [ADAPT-Teleop](https://www.nature.com/articles/s44182-025-00034-3) 从掌骨朝向提取 CMC 控制量的几何思路，以及 [重定向目标分析](https://mingrui-yu.github.io/retargeting/) 将姿态目标与关节约束结合的思路。本地适配使用已有单目 21 点，新增混合根部引导，不是论文系统复现。ADAPT 的 AVP 输入和两轴 CMC 与 LH20 不同，不能直接照搬其轴角。

默认 `agile` 在已对齐的掌部坐标系中取第一段单位方向 u=(MediaPipe 2−1)/骨长，第二段 v=(3−2)/骨长：yaw 引导为 1.25×(atan2(u_z,−u_y)−15°)，roll 为 0.12 rad+1.8×atan2(u_x,hypot(u_y,u_z))，pitch 为 1.3×acos(u·v)。结果截到原厂家根部范围。pitch 的引导源是人手 MCP 夹角；它是针对不同机构的控制映射，不是对三个人体 CMC 欧拉角的测量。数值是当前可回退实验参数，未完成逐轴实物标定。

四轴方向优化仍保留三段单位方向和上一帧连续性项。在目标中增加根部角度引导二次项，权重 0.6、轴向比例 [1,1,2]；仅相机有效观测启用，MCP 独立轴继续由三段方向拟合。这样让根部显式控制意图参与求解，减少全部运动被 yaw 或指节弯曲代替。引导每帧设置、只消费一次；无效点清除引导并拒绝该帧。原厂家限位、swapped、滤波、速度、反馈、卡滞及逐步 CAD 均保留。

`./lh20-left vision vector` 默认启用新模式；附加 `--thumb-root-mode directions` 恢复此前 v2。预览、自动会话和内部相机入口均传递此参数。日志用 `anatomical_root_guide_v3` 区分，记录根部引导角、模式、权重及映射增益。单纯模型 `--self-test` 不设置人手几何引导，仍只检查 IK/限位/mimic；新增几何特征、逐轴响应/反向、带引导梯度和静止噪声回归专门检查新分支。

五段共 10179 帧同输入回放中，最新会话 roll/pitch 的低于 5° 比例降至 28.0%/0.7%；相对所定义几何控制量的角度差中位数从 [15.4°,19.3°,21.1°] 降至 [3.8°,5.4°,2.2°]。后者只是“请求控制量被优化器保留多少”，不是真实机械角度误差，也不能用低角度帧比例代替灵敏度测量。新增受控合成手势测试分别改变三个输入并验证对应轴响应和反向。

该模式优先根部控制，存在明显代价：五段拇指末段相对原始人手骨段的方向误差 P95 约从 [33.8°,28.0°,18.4°,34.4°,36.4°] 变为 [47.8°,33.6°,28.7°,45.4°,54.2°]。最新会话每十帧量化终点 CAD 抽样无接触数由 149/164 降至 139/164；实际控制桥会拒绝或部分暂停受阻路径。不能宣称姿态精度、抓取成功率或实际电机响应全面改善，实机待使用者验收。可根据任务直接切回 `directions`。

### 2026-11-02 独立拇指方向细化

默认 Vector / `segments` 现在用本地 `ThumbResponsiveOptimizer` 扩展固定版本 Vector；上游子模块不修改。第一阶段仍求解原十一组向量；第二阶段只求解拇指四轴，以 MediaPipe 1→2、2→3、3→4 三段单位方向的平均平方差为任务，三段权重相同。梯度包含方向归一化和 mimic 链式求导，连续性项同时进入损失值和梯度。它不加入曾使实机变差的 palm 位置约束，不增加捏合锁定、姿态预设或额外关节软限位。

拇指阶段以最后一次细化姿态作为初值，连续性权重 0.003；这样减少从原骨长拟合结果跳到另一逆解分支的情况。厂家四轴边界保持精确值；低于 3 mm 或非有限的拇指观测拒绝该帧，不把旧拇指悄悄配上新四指目标。原速度自适应滤波保留，并重新展开 mimic。

旧视觉端发现最终目标有接触就拒绝整帧，即使实际机械手离该目标很远，也会使控制桥的部分跟随机制失去输入。新版 Vector 用 `cad_validation=bridge_path_v1` 明确区分：视觉端只检查量化目标的接触并记录 `cad_collision_hits`；有限性、模型范围、厂家 raw 编码仍必须有效。控制桥接受这种目标请求后，仍从新鲜实物反馈出发，对限速候选调用原完整路径 CAD 检查和部分跟随选择；只有检查通过的候选才能提交、发布。新碰撞和加深已有接触仍阻止实际路径，无法确认深度仍停止该候选。旧流、palm、DexPilot 保留原最终目标拒绝策略，未知策略拒绝。

日志中 `valid=true` 表示有效目标请求；同时有 `cad_collision_hits` 时并不代表允许机器人到达该姿态。预览显示请求姿态与接触提示，实际执行以 `live_hand` 日志为准。新版只检查一次量化目标网格，省去重复的未量化视觉网格查询。新日志记录 `vector_thumb_target=independent_directions_v2`、初值方式、连续性权重及三段权重。

四段历史输入共 8546 帧的同输入回放，拇指末段方向误差 95 分位依次从 35.6°、31.9°、23.9°、36.8° 降至 33.8°、28.0°、18.4°、34.4°；这些是模型相对人手关键点的方向指标。第一段末段中位误差从 3.8° 增至 7.4°，部分根部和中段指标也有取舍。第四段量化目标每十帧抽样，无接触数从 452/454 降至 432/454，因此目标更灵活不等于所有目标都能实际执行；控制桥会限制这些实际路径。不能据此宣称实机准确率或抓取率改善。

合成 30 FPS 阶跃中，全部四个拇指关节越过 90% 目标变化量，闭合由 21 帧变成 2 帧，反向张开新版为 5 帧，旧版在 30 帧观察窗口内未全部到达。该数字只计求解和视觉滤波，不含摄像头、桥接限速、CAD、反馈或电机。求解耗时中位数约从 1.5–1.7 ms 增至 2.0–2.3 ms。四指向量定义保留；整体第一阶段的迭代仍会造成四指角度差异，四段 95 分位约 0.015、0.015、0.019、0.022 rad。

可用 `teleop/vision/benchmark_thumb.py <视觉记录...> --output <新JSON路径>` 复现离线对照；不连接摄像头、ROS 或设备。85 项离线测试通过，包括方向梯度数值核对、骨长不变性、快速反向、静止噪声、mimic、接触目标流转及真实网格拒绝加深接触。实机尚未重新运行。

以下为此前版本和实验的历史记录。

2026-10-25 Vector 优化：默认 `segments` 从原十组骨段向量增加为十一组，新增 `thumb_distal`→固定 `teleop_thumb_tip` 对应 MediaPipe 3→4。原十组目标、厂家物理模型、swapped 转换和控制桥不变。临时 FK 模型按末节网格生成固定指尖，不增加自由度，也不替代物理标定。相机线程仅保留最新帧，以读取完成时间作时间戳；这不是曝光时间。停止或无新帧不会重放旧图像，桥接端仍按原时效和限位检查目标。

实时 Vector 使用速度自适应 EMA：静止时保持原 alpha=0.6，以真实帧间隔低通估计关节速度（1 Hz），按速度提高截止频率（beta=4）减少运动时滤波滞后。该实现借鉴 One Euro 的速度适配思路，并按每帧间隔保持原静态 EMA 权重；不是对未来姿态做预测。过滤后重新展开 mimic，避免各轴不同滤波系数改变机械耦合。超过 250 ms 的观测间隔重置滤波状态；最终目标仍由原控制桥按角速度、反馈和 CAD 约束执行。

目标在模型绘制、打印及记录写入之前发送，记录包括 `camera_frame_seq`、`vector_thumb_target=three_segments_v1`、`joint_filter=speed_adaptive_v1` 和分段 `timing_ms`。自动 Vector 会话与 DexPilot 一样保存关键点和角度，不保存相机图像。原 `low_pass_alpha=0.6` 仍用于模型自检及旧 palm 实验；新版实时滤波不应与模型自检混称端到端实机验收。

2026-10-25 实机反馈：`palm` 使这只手的拇指效果变差，四指尚可。当前应使用默认 `segments`；以下 palm 方案仅保留为失败实验记录，不再推荐用于这只实机。模型生成输入的精度改善不能代替实机验证。

默认 `--thumb-profile segments` 保留原来的指骨向量目标，并增加上述拇指尖方向。可选旧 `--thumb-profile palm` 使用原十组目标，并增加食指 MCP 到拇指 IP 的相对位置向量（MediaPipe 5→3；模型 `index_proximal`→`thumb_distal`）；它不含新版指尖目标。该实验用于减少“骨节方向接近但拇指整体位置偏移”的歧义，不改变 swapped 接线适配、厂家 raw 转换、关节范围或速度上限。

```bash
./lh20-left vision --scope hand --thumb-axes swapped --thumb-profile palm
```

六组模型生成姿态的拇指 IP 相对位置误差均值约 4.0→1.5 mm；这只验证优化目标，不等于实物标定或真人手势精度。手掌比例、关节零位与真实软组织仍未测量。恢复旧目标使用 `--thumb-profile segments`。可加 `--preview` 仅对比视觉模型，或用 `--record` 保存新的视觉 JSONL 供进一步分析。
